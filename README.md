# Firework 直播间

第一阶段实现摄像头预览、单人面部关键点与轮廓追踪。界面使用现有 414 × 896 直播间作为基准，小屏等比缩放。

## 本地启动

使用 Node.js 22.12+ 的 Node.js 22，或 Node.js 24 / 26。

```sh
npm install
npm run dev
```

打开终端显示的 localhost 地址，点击「开启摄像头」。在手机上试用时请使用部署后的 HTTPS 地址。

## 目录

```text
index.html       直播间及调试控制
style.css        直播间布局与图层
assets/          顶部、底部图片及原始素材
src/
  main.js        会话生命周期、逐帧检测与状态
  camera.js      摄像头授权与前置摄像头偏好
  tracker.js     MediaPipe 初始化与轮廓连接定义
  overlay.js     视频裁切、镜像与关键点绘制
netlify.toml     Netlify 构建配置
vercel.json      Vercel 构建配置
```

## 构建和 HTTPS 部署

运行 `npm run build`，产物位于 `dist/`。可用 `npm run preview` 本地查看构建结果。将 GitHub 仓库导入有权限的 Vercel 或 Netlify 项目即可按仓库配置构建，也可上传构建产物到支持 HTTPS 的静态托管。浏览器需要能访问 jsDelivr 上的 MediaPipe WASM 和 Google Cloud Storage 上的模型。摄像头画面和推理都在浏览器内处理。

## 第一阶段测试

1. 在桌面 Chrome 打开 localhost 页面。点击开启摄像头并允许权限，确认镜像画面、点线叠层、FPS 与「追踪中」状态出现。FPS 表示每秒实际处理的视频帧数。
2. 左右移动、转脸、倾头并调整窗口宽度，确认点线贴合眼睛、嘴唇和脸部边缘。脸离开画面时应清除叠层并显示「未检测到」。
3. 取消「显示关键点」，确认点线消失、预览和检测状态持续更新。重新勾选后点线应恢复。
4. 点击关闭，确认预览和叠层清除、摄像头指示灯熄灭。再次开启应恢复追踪。
5. 重置浏览器的摄像头权限并拒绝，确认页面显示权限提示。恢复权限后应可重试。
6. 在浏览器开发工具中阻止 `*.task` 模型请求并禁用缓存，确认模型加载失败提示出现且摄像头释放。解除请求拦截后重试。
7. 在手机上打开 HTTPS 链接，确认优先使用前置摄像头、视频在页面内播放，旋转手机后叠层仍能对齐。

## 自动化评测

需要 Node.js 22.12+ 和已安装的 Google Chrome。安装依赖后执行以下命令。

```sh
npm ci
npm run test:stage1
```

命令先跑 Vitest、构建应用，再使用 Playwright 在隔离端口启动生产预览。模拟摄像头性能测试约需两分钟。需要访问 MediaPipe 模型和 WASM 的 HTTPS 地址。阶段未通过时进程以 1 退出，报告仍会生成。

- `reports/test-report.json` 分数、实测、环境、日志、截图路径及验收状态
- `reports/test-summary.md` 开发者摘要
- `test-results/` 原始运行结果与失败截图

合法视频与人工标注见 `tests/fixtures/README.md`。页面底部的 Debug 开关会显示关键点数量、鼻尖归一化坐标和最近一次推理耗时。模拟移动视口的结果只用于评估布局和重载。

失败项按 P0/P1/P2 排序并给出定位和修复建议。若有已审核的业务源码补丁，可将路径以逗号分隔传给 `STAGE1_REPAIR_PATCHES`。命令只在检测到失败时尝试应用，最多三轮，每轮先重测优先级最高的受影响项，再跑完整回归。补丁不能更改测试、评分、阈值或诊断数据。未提供修复补丁时，命令生成问题清单供开发者处理。

实机验收按上方测试步骤操作，保存设备、浏览器、测试日期、执行者和实测说明。可通过 `STAGE1_DEVICE_EVIDENCE=/absolute/path/evidence.json` 引入记录。顶层可含 `PC`、`MOBILE`、`HTTPS`，各项有 `status`、`date`、`tester`、`details`。摄像头通过记录还需提供 `camera: "real"`、`device`、`browser`、`permission: true`、`alignment: true`、`reacquired: true`。移动端还需记录 `fps`、`frontCamera: true`、`rotation: true`。公网记录需要 `url`、`accessible: true`、`permission: true`。这些字段是外部实测记录，报告标明其来源。模拟测试无法替代实机验收。

## 真人对齐诊断

打开摄像头并启用 **Debug**。每到一个测试姿态，点击「暂停并标注」。画面暂停后选择对应场景，放大查看，依次选中五官名称并点击画布。标注可以拖动，画布坐标以冻结时镜像画面的左上角为原点，单位是 CSS 像素。使用人物自身左右，镜像画面里人物左侧在屏幕左侧。预测默认隐藏，完成标注后可开启预测和编号对比。

确认画面来自真实摄像头且参考点由人工标注，再点击「保存场景」。返回实时画面，分别采集其余姿态。转头和倾斜幅度以五个参考点仍清晰可见为准。放大后可用「滑动查看」移动画面，关闭它即可继续拖点。同一场景可重新采样覆盖，同一帧只用于一个场景。保存记录保留至页面刷新；建议随时导出。JSON 包含坐标、采样时间和误差，画面图像留在设备上。

误差按人工标注双眼外眼角间距归一化。六个场景共 30 点，平均误差和全局方向偏差均 ≤ 5%，且左右对应正确时，真人对齐可以获得 12 分。阈值为本 Demo 的验收目标。报告重新计算导出坐标的误差，摄像头来源和人工标注由采样者确认。

将导出的 `face-alignment.json` 放入 `reports/` 后运行 `npm run test:stage1 -- --alignment-only`。也可通过环境变量 `STAGE1_ALIGNMENT_EVIDENCE` 指定绝对路径。单项导入只更新真人对齐的 12 分和阶段结论，保留已有评测记录。人工标注视频检测率和真实设备验收依然按原流程记录。

## 头部空间互动验证

在直播间点击「开启摄像头」，然后勾选 **Debug → 碰撞预览**。青色小点是周围测试粒子，黄色表示刚受到推动或仍在明显运动。「显示边界」可独立关闭黄色轮廓；「重置周围粒子」在当前头部附近重新布点。定向测试火星可继续使用。头部边界由多类别分割中的头发和面部皮肤区域计算，使用连通区域的凸包。首次开启需要下载额外模型。

位置与尺寸使用镜像、裁切后的画面坐标（CSS px）。速度用相邻追踪结果的实际时间差换算成 px/s，方向以屏幕向右为 0°、向下为 90°。尺寸沿估算的头部倾角测量，缩放相对于当前连续追踪开始时的尺寸。Yaw、Pitch、Roll 是由关键点相对位置与深度导出的估计角度，不是经相机标定的三维姿态。头部区域通过分割估计，发型、遮挡和大角度转头仍可能影响贴合。长发也可能进入碰撞范围。

使用 `npm run test:head-space` 重跑新增验证。输出位于 `reports/head-space-report.json` 与 `reports/head-space-summary.md`，独立于第一阶段评分。几何用例验证位置、缩放、旋转、速度、边界同步和粒子受推。Chromium 模拟摄像头通过真实模型推理检查推动、丢失清理和恢复。

真人验收依次记录左右移、上下移、远近变化、左右歪头、快速横移、离开画面和重新入画。观察边界同步、粒子明显位移、静止后趋稳，以及丢失后清屏和重新跟踪。在记录中写明设备、浏览器和每个动作的结果。自动报告保留真人项目为 BLOCKED，直到有实际摄像头验收记录。

## 阶段 1.5 人体表面与水珠

开启摄像头，勾选「阶段 1.5 人体水珠测试」。请后退一些，让头顶、双肩和上半身进入画面。模型就绪后点击「释放测试水珠」。每次释放少量蓝色测试水珠，重力使其下落。接触曲面后附着并沿切向重力滑动，到下侧、分割区域外或附着时间上限时脱离。人物突然平移或转动会给附着水珠施加惯性力，达到阈值时甩出并生成少量飞溅。

表面调试显示绿色人体分割轮廓、黄色近似碰撞曲面、紫色局部法线、白圈附着水珠及速度线。Pose Landmarker 的肩膀、髋部和头部姿态与 Image Segmenter 的头发、皮肤、衣服区域共同驱动模型。双肩可见时才能启动，髋部不在镜头内时按肩宽估计躯干长度。

近似 2.5D 模型由带深度的头部、左右肩、躯干椭球曲面构成。深度来自姿态点的相对 z 和人体比例估计，使用局部法线、切向重力、阻尼及实际时间差计算的表面速度和加速度。人体分割限制可接触区域。水珠以固定小步长积分，飞行轨迹与曲面做连续相交检测。模型在独立 Worker 中推理，避免积压摄像头帧。关闭模式或摄像头后释放处理线程；追踪超过 750 ms 未更新时清理旧表面。

运行 `npm run test:stage1.5` 生成独立的 `reports/surface-report.json` 和 `reports/surface-summary.md`。实机验收请依次测试头顶附着与滑落、抬肩改变滑动、躯干倾斜、快速晃头甩出、人物离开与返回。记录设备、浏览器和每个动作结果。模拟素材只支持检查模型接线和物理状态变化，报告中的真人验收须由实际摄像头操作完成。

当前属于工程近似。宽松衣服、长发、遮挡以及曲面连接处可能偏离真实表面。z 为估计值，模型推理频率取决于设备。分割不表示真实物理深度或材质。

### 阶段 1.5 雨滴质量评测

`npm run test:stage1.5` 在原报告中加入 `quality`。评测浏览器读取实际参与合成的水珠 Alpha 图层，按逐帧人脸轮廓统计覆盖率，无脸帧不参与统计。调试标记不计入特效。头顶事件按水珠 ID 记录位置、速度、法线和响应。当前事件使用物理求交结果作为预期，尚缺独立轨迹真值。报告单独标识即时飞溅缺失以及实际避雨遮罩缺失。

通过数值阈值的合成素材测量仅标为 PARTIAL。完整验收需要标准化真人素材和避雨遮罩的实际输出，还需要对照录像复核五官遮挡和头顶贴合。


## 摄像头取景

预览默认将镜像摄像头画面等比填满 414 × 896 区域。优先请求前置摄像头的 720×1280 竖屏帧。在控制面板可切换竖屏和横屏视频展示，直播间始终按 414 × 896 等比布局。竖屏默认居中裁切并锁定。头部或双肩超出范围时显示调整提示。点击「重新取景」可用新的可靠人体结果重新锁定裁切中心。等待期间暂停碰撞，如果 2.5 秒内无法取得满足条件的结果，就保留之前的裁切。横屏在房间中部按源比例完整显示摄像头画面。展开默认收起的「Debug」后，「Camera Debug」可以查看原始帧、轨道设置、容器、缩放、裁切、当前模式、渲染 FPS 和视频帧间隔。页面使用浏览器选出的摄像头和 zoom 参数。

构图检测在打开摄像头后启动。请让头顶、双肩和胸口入镜。引导会优先显示裁切、距离或位置问题。理想和可接受构图都可进入人体水珠测试。短暂动作会经过时间过滤，追踪不可靠的碰撞区域会暂停参与计算。

运行 `npm run test:framing` 检查构图逻辑。浏览器测试可运行 `npm run build` 后执行 `npx playwright test tests/framing.spec.js`。
